# 0002. サイズの表記と計算規則

- 状態：承認済み
- 日付：2026-09-30

## 背景

パーティションと LVM の論理ボリューム（LV）には、サイズを指定する必要があります。
実際の構成では、固定のサイズ（ESP の 1GiB など）と、残りの領域を使う指定の両方が現れます。
さらに、残りの領域を複数の要素で分けたい場合もあります（「1GiB、50%、50%」のような並び）。

サイズの計算結果は、作られるパーティションや LV の大きさを決めます。
構成済みのデバイスに再適用するときは、既存のサイズが宣言を満たしているかの判定にも使います。
そのため、計算規則は宣言だけから一意に決まり、再適用のたびに同じ結果になる必要があります。

## 判断

### 表記

サイズは、次のどちらかで書きます。

- **固定サイズ**：整数と二進接頭辞の単位の組です（`512MiB`、`1GiB`、`4TiB` など）。
  単位は `KiB`、`MiB`、`GiB`、`TiB` を受け付けます。
- **パーセント**：1 から 100 の整数に `%` を付けたものです（`50%`、`100%` など）。

次の表記はエラーにします。

- 単位のない数値
- 十進接頭辞の単位（`GB` など）
- 小数（`1.5GiB`、`33.3%` など）
- `rest`、`remaining`、`100%FREE` などのキーワード

### パーセントの基準

パーセントは、**基準量**に対する割合です。
基準量は、親の利用可能な容量から、同じ親に宣言された固定サイズの合計を引いた量です。

- ディスクでは、パーティションテーブルが利用可能とする領域を、親の容量とします。
- ボリュームグループ（VG）では、VG の容量を親の容量とします。

基準量は宣言だけから計算し、現在の空き容量は使いません。
宣言にない既存の要素（宣言されていない LV など）が親にある場合は、サポートしていない既存構成として拒否します。

「1GiB、50%、50%」は、1GiB を引いた残りを半分ずつに分けるという意味になります。
`100%` は、固定サイズを引いた残りのすべてを意味します。
パーセントは宣言の位置に関係なく、固定サイズをすべて差し引いてから計算します。

### 合計

同じ親に属するパーセントの合計が 100% を超えたら、エラーにします。
100% 未満の場合、その差の分は未割り当てのまま残します。

固定サイズの合計が親の容量を超える場合と、基準量が 0 以下になるのにパーセント指定がある場合も、エラーにします。

### 丸め

サイズは、アラインメントの単位に合わせて丸めます。
単位は、パーティションでは 1MiB、LV では VG の物理エクステント（PE）のサイズです。

- 固定サイズは、単位の倍数に切り上げます。
  宣言したサイズを下回らないようにするためです。
- パーセントは、単位の倍数に切り捨てます。
  合計が親の容量を超えないようにするためです。

パーセントの合計がちょうど 100% の場合も、切り捨てによって単位未満の端数が要素ごとに残ることがあります。
この端数は、未割り当てのまま残します。

### 表示

plan では、計算後の絶対サイズを表示します。

### 例

以下の例では、親の利用可能な容量を仮の値で示します。
宣言の構造は別途決めるので、ここではサイズの並びだけを示します。

利用可能な領域が 1025GiB のディスクに、パーティションを次のように宣言した場合です。

```yaml
- {name: esp, size: 1GiB}
- {name: a, size: 50%}
- {name: b, size: 50%}
```

基準量は 1025GiB − 1GiB = 1024GiB です。
`a` と `b` は、それぞれ 512GiB になります。

容量が 880GiB の VG に、LV を次のように宣言した場合です。

```yaml
root: {size: 64GiB}
swap: {size: 16GiB}
var: {size: 90%}
```

基準量は 880GiB − 64GiB − 16GiB = 800GiB です。
`var` は 720GiB になり、残りの 80GiB は未割り当てのまま残ります。

丸めによって端数が残る場合もあります。
利用可能な領域が 1001MiB のディスクに `50%` を二つ宣言すると、500.5MiB を 1MiB 単位に切り捨てて、どちらも 500MiB になります。
残りの 1MiB は未割り当てのまま残ります。

次の宣言は、パーセントの合計が 110% になるので、エラーにします。

```yaml
- {name: a, size: 60%}
- {name: b, size: 50%}
```

## 検討した代替案

### `rest` や `remaining` のキーワード

残りの領域を一語で表せます。
しかし、残りを複数の要素で分ける指定（「50%、50%」）には別の表記が必要になり、キーワードとパーセントという二つの概念を持つことになります。
パーセントの基準を「固定サイズを引いた残り」と定義すれば、`100%` が残りのすべてを表すので、キーワードは不要になります。

### disko の表記

disko は、パーティションでは `100%` を残りの意味で使い、LV では `lvcreate` に渡す `100%FREE` を使います。
diskform では、パーティションと LV で同じ表記と同じ意味を使えるほうを選びました。

### 親の容量全体に対するパーセント

parted の `100%` はこの意味（ディスク全体に対する位置）です。
この定義では「1GiB、50%、50%」の合計が親の容量を超えてしまい、直感的な並びが成り立ちません。

### 端数を最後の要素に吸収させる

パーセントの合計が 100% のとき、端数を最後のパーセント指定に足せば、未割り当ての端数が残りません。
採らなかったのは、LV のように名前で引く要素では、JSON のオブジェクトが順序を保証しないためです。
「最後」の意味が形式によって変わる規則を避け、順序に依存しない切り捨てを選びました。

## 制約

- パーセント指定のサイズは、親の容量に依存します。
  ディスクを別の個体に交換すると、容量の差によって計算結果が変わる可能性があります。
- 再適用のときは、既存のサイズと計算結果の差がアラインメントの単位以内であれば、宣言を満たしていると見なします。
  それを超える差は、エラーにします。
  どちらの場合も、リサイズや作り直しはしません。
- この判定は冪等性に関わるので、apply 層のテストで検証する必要があります。
- 小数のパーセントや、親の容量全体に対するパーセントが必要な例が現れたら、この判断を見直します。
