# 0003. 対象ディスクの照合規則

- 状態：承認済み
- 日付：2026-09-30

## 背景

宣言の `disk` は、実際のどのブロックデバイスを対象にするかを、照合の条件で指定します。
照合を誤ると、意図しないディスクを操作し、データを失うおそれがあります。

照合の方法を選ぶうえで、次の要求がありました。

- 同じ機種のマシンに、同じ宣言を大量に展開できること。
  マシンごとにシリアルを調べて書き換える運用はできません。
- 一台のマシン向けの宣言では、対象を個体として特定でき、人が読んで対象がわかること。
- 同じモデル、同じ容量のディスクが複数あっても、それぞれを区別できること。
- apply 層のテストで、ループデバイスを対象にできること。

## 判断

### 条件

照合の条件は、次の二つです。

- **`path`**：`/dev/` から始まる絶対パスです。必須です。
- **`min_size`**：デバイスの最小容量です。省略できます。表記は ADR 0002 の固定サイズと同じで、パーセントは受け付けません。

条件はすべて AND で評価します。

`path` には、`/dev/disk/by-id/`、`/dev/disk/by-path/` の下の名前や、`/dev/loop0` のようなカーネルの名前を書けます。
利用者は用途に応じて名前を選びます。
一台向けの宣言には by-id を、同じ機種への展開には by-path やワイルドカード付きの by-id を使うことを想定しています。

### ワイルドカード

`path` の最後の要素（ファイル名の部分）には、ワイルドカード（`*`、`?`、`[...]`）を使えます。
それより前のディレクトリの部分には使えません。

### 照合の手順

照合は、次の手順で行います。

1. `path` に一致するパスを列挙します。
2. 各パスのシンボリックリンクを解決し、ブロックデバイスの集合を得ます。
   同じデバイスに解決されたパスは、一台として数えます。
3. ディスク全体でないデバイス（パーティション、device-mapper、md）を候補から除きます。
4. `min_size` を満たさないデバイスを候補から除きます。
5. 候補がちょうど一台なら、それを対象とします。
   零台または二台以上なら、拒否します。

拒否するときのエラーでは、原因を区別して示します。
区別する原因は、パスが存在しない場合、パーティションなどには一致したがディスクには一致しなかった場合、二台以上に一致した場合、容量が `min_size` に満たない場合です。

宣言の二つの `disk` が同じデバイスに解決された場合も、拒否します。

### カーネルの名前への警告

`/dev/disk/by-` で始まらないパス（`/dev/sda`、`/dev/nvme0n1`、`/dev/loop0` など）も受け付けます。
ただし、これらの名前は起動のたびに割り当てが変わりうるので、plan で警告します。

### 表示と再検証

plan では、`disk` ごとに、解決したデバイスのパス、モデル、シリアル、容量を表示します。
破壊を伴う操作の直前には照合をやり直し、plan で示したデバイスと同じであることを確認します。

## 検討した代替案

### シリアルによる照合

個体を確実に特定できます。
しかし、マシンごとに値が違うので、同じ宣言を大量に展開する用途に使えません。

### by-id と by-path を別々の条件にする

`by_id` と `by_path` のように、名前の種類ごとに条件を分ける案です。
`/dev/` からのパスを一つの条件で受け付ければ、どちらも同じ仕組みで扱えます。
ループデバイスも特別な条件なしに指定できるので、条件を分ける理由がありません。

### 複数台に一致する照合

条件に一致するディスクの台数を宣言させ（二台、など）、同じモデルのディスクをまとめて指定する案です。
raid1 のメンバーのように、どの個体がどの役割でもかまわない場合には自然な書き方です。
採らなかったのは、個体と役割の対応を何らかの順序で決める必要が生じるためです。
「ちょうど一台」の規則を保てば、どのディスクがどの役割かが宣言から一意に決まります。

### パスの数で「ちょうど一台」を判定する

by-id には、同じディスクを指す別名や、パーティションを指す名前が並んでいます。
パスの数で判定すると、ワイルドカードを使った照合がほとんど常に拒否されてしまいます。

### カーネルの名前を拒否する

起動ごとに変わりうる名前を使わせないので、安全側の選択です。
しかし、テストで使うループデバイスもカーネルの名前なので、例外の規則が必要になります。
誤って一致しても、既存のデータがあるディスクは下記の前提により壊れないので、警告にとどめました。

### 個体を特定する条件を必須にする

`min_size` だけのような緩い照合を防げます。
しかし、大量展開の要求と両立しないので採りませんでした。
`path` を必須にし、「ちょうど一台」の規則で一致の範囲を制限します。

## 制約

- 同じモデル、同じ容量のディスクが複数ある場合、ワイルドカード付きの by-id では区別できず、拒否されます。
  そのようなディスクは、by-path などの接続位置で指定する必要があります。
- by-path の名前は、拡張カードの増設やファームウェアの設定の変更で、PCI のアドレスが変わると変わることがあります。
- カーネルの名前で指定した場合、空のディスクが同じ容量で複数あると、役割が入れ替わったまま構成される可能性があります。
- この照合規則は、誤って一致したディスクに既存のデータがあっても、apply がそれを消さないことを前提にしています。
  既存のデータの消去は destroy サブコマンドに分ける方針であり、その規則は別の ADR で確定させます。
