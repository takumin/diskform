# 0005. 宣言の構造と参照の文法

- 状態：承認済み
- 日付：2026-10-02

## 背景

宣言には、パーティション、LUKS、LVM、ファイルシステム、swap を積み重ねた構成を書きます。
この積み重ねは、常に木の形になるとは限りません。
btrfs の raid1 や複数の PV からなる VG のように、複数のディスクにまたがる構成では、一つの対象が複数の下位のデバイスを使います。

宣言の構造を決めるうえで、次の要求がありました。

- 木に収まらない構成も、木に収まる構成と同じ書き方で表せること。
- どの対象がどのデバイスを使うかが、宣言から一意に読み取れること。
- 誤った組み合わせ（同じデバイスの二重使用、循環など）を、デバイスに触れる前に検出できること。
- YAML と JSON のどちらでも、同じ意味に解析できること（ADR 0001）。

## 判断

### 全体の構造

最上位には、`version` と、種別ごとの節（`disk`、`luks`、`lvm`、`filesystem`、`swap`）を置きます。
`version` は必須で、現在の値は `1` です。
各節は、名前をキーにした写像です。

層の積み重ねは、入れ子ではなく参照で表します。
入れ子にするのは、親と寿命を共にする子だけです。

- **partition**：`disk` の中に、リストで書きます。
- **LV**：`lvm` の VG の中に、写像で書きます。
- **subvolume**：`filesystem` の中に、写像で書きます。

partition だけをリストにするのは、ディスク上の並びと番号に順序があるからです。
LV と subvolume には意味のある順序がなく、ADR 0002 のサイズ計算も順序に依存しないので、写像にします。

未知のキーはエラーにします。
同じキーの重複も、YAML と JSON のどちらでもエラーにします。
JSON の解析器には重複したキーを後勝ちで受け付けるものがあるので、明示的に検査します。

### 名前

名前に使える文字は、`[a-z0-9][a-z0-9_-]*` に制限します。
名前はドットを含まないので、参照を一意に分解できます。
名前は節ごとに独立しており、子の名前は親ごとに独立しています。

VG、LV、LUKS のマッピングには、宣言の名前をそのまま使います（`/dev/vg0/root`、`/dev/mapper/cryptsys` など）。
これらの名前はマシン全体で一意でなければならないので、既存のものと衝突する場合は拒否します。
`disk` の名前は、システム上には現れません。

### 参照の文法

参照は、`<種別>.<名前>` または `<種別>.<名前>.<子の名前>` の形の文字列です。
partition は `disk.sys0.esp`、LUKS は `luks.cryptsys`、LV は `lvm.vg0.root` のように書きます。

参照には、次の規則を設けます。

- 参照できるのは、ブロックデバイスを生む対象（partition、LUKS、LV）だけです。
  `disk`、VG、`filesystem`、`swap` への参照は、エラーにします。
- 一つのデバイスを参照できる利用者は、一つだけです。
  同じデバイスを二つの対象が参照した場合は、エラーにします。
- 参照の循環は、エラーにします。
- どこからも参照されないデバイスは、エラーにしません。
  plan で未使用として示します。

### 種別ごとの設定

- **`filesystem` のデバイス**：単一のデバイスは `device` で、複数のデバイスは `devices` で指定します。
  `devices` は `format` が btrfs のときだけ受け付けます。
  `device` と `devices` の両方を書いた場合は、エラーにします。
- **形式に固有の設定**：形式名のブロック（`btrfs` など）に書きます。
  `format` と一致しないブロックは、エラーにします。
  `subvolumes` も、btrfs のときだけ受け付けます。
- **swap**：`filesystem` とは別の節に書きます。

## 検討した代替案

### disko のような入れ子

disk の中に partition、その中に LUKS、さらにその中に PV を書くように、積み重ねをそのまま入れ子で表す案です。
木に収まる構成では、上から下へ一続きに読めます。
しかし、複数のディスクにまたがる構成は木に収まらず、disko も md や VG を最上位に出して名前で結んでいます。
例には二台にまたがる btrfs が含まれるので、入れ子を基本にすると、最初から例外の書き方が必要になります。

### オブジェクトによる参照

`{disk: sys0, partition: esp}` のように、参照をオブジェクトで書く案です。
分解の規則が不要になります。
しかし、名前の文字を制限すれば文字列でも曖昧さは生じず、文字列のほうが短く読めます。

### filesystem のデバイスを常に `devices` で指定する

キーが一つになり、規則が単純になります。
しかし、単一のデバイスに作るファイルシステムがほとんどなので、多くの宣言で要素が一つのリストを書くことになります。

### swap を `filesystem` の `format: swap` で書く

節が一つ減ります。
しかし、swap はマウント先を持たず、`mount` でも有効にしないので（ADR 0004）、`filesystem` の多くの設定が無意味になります。
それらを swap のときだけ拒否する規則を足すより、節を分けたほうが単純です。

### 参照されないデバイスをエラーにする

宣言の書き忘れを検出できます。
しかし、BIOS boot 用のパーティションのように、意図して何も載せないデバイスがあります。

## 制約

- 宣言の名前を VG、LV、LUKS のマッピングの名前に使うので、宣言の名前を変えると、システム上の名前も変わります。
- 流用したディスクに同名の VG があるなど、既存の名前と衝突する場合は、宣言の名前を変えるか、`destroy` で既存の構成を消す必要があります。
- md など、まだ例のない種別の節は定めていません。
  例が必要としたときに、この構造に沿って追加します。
- partition の名前を PARTLABEL に書くかどうかは、再適用での同定方法と一緒に決めます。
