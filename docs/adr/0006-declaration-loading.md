# 0006. 宣言ファイルの読み込み

- 状態：承認済み
- 日付：2026-10-02

## 背景

ADR 0001 は、YAML のパーサーの選定を実装の時点に先送りしていました。
選定にあたっては、次の要求を満たす必要がありました。

- 期待する型と異なる値を、暗黙に変換せずにエラーにすること（ADR 0001）。
- 同じキーの重複を、YAML と JSON のどちらでもエラーにすること（ADR 0005）。
- MSRV の 1.85 でビルドできること（AGENTS.md 7 章）。

候補のパーサーを試したところ、どれもそのままでは要求を満たしませんでした。

- serde_yaml、serde_norway、serde-saphyr のいずれも、文字列を期待する項目に書かれた `123` や `true` を、文字列として受け付けます。
- serde_norway と serde_json は、写像（`BTreeMap` など）に読み込むとき、重複したキーを後勝ちで受け付けます。
  構造体のフィールドの重複は serde の derive が拒否しますが、名前をキーにした節（`disk`、`lvm` の `volumes` など）は写像なので、検出されません。
- serde-saphyr には、引用符のない数値や真偽値を文字列として受け付けないオプション（`no_schema`）があります。
  しかし MSRV が 1.89 で、引用符付きの `"1"` を整数として受け付けます。
- serde の derive は、構造体を写像だけでなく、列からも位置で読み込みます。
  そのため、`[p1, 1GiB]` のような列が partition として受け付けられてしまいます。

## 判断

YAML は serde_norway で、JSON は serde_json で解析します。
どちらの形式も、いったん形式に依存しない値の木に読み込み、モデルはその木から読み込みます。

値の木を作る段階では、次を拒否します。

- 同じ写像の中での、キーの重複
- 文字列でないキー（YAML の `1:` や `0o17:` など）
- null（`~`、`null`、値のないキー）

null は、宣言のどの項目でも意味を持たないので、一律に拒否します。
項目を省略したいときは、キーごと省きます。
文書全体が空の場合（空のファイル、コメントだけのファイル、JSON の `null`）は、「宣言が空である」という別のエラーにします。

値の木からモデルを読み込む段階では、次の規則を設けます。

- 構造体は、写像からだけ読み込みます。
- 値の型を変換しません。
  文字列を期待する項目に数値や真偽値が書かれていれば、拒否します。
  逆に、数値を期待する項目（`version`）に文字列が書かれていても、拒否します。

YAML のスカラーの型は、serde_norway の解決に従います。
YAML 1.2 の core schema に沿っており、`yes` や `no` は文字列、`0o17` は整数になります。
文字列として書きたい値は、引用符で囲みます。

YAML のアンカーとエイリアスは、パーサーが展開したものを受け付けます。
マージキー（`<<`）は特別に扱わず、通常のキーとして読むので、未知のキーとして拒否されます。
複数の文書を含む YAML は、拒否します。

## 検討した代替案

### serde-saphyr

型の厳密さと重複キーの拒否を、オプションで指定できます。
採らなかったのは、MSRV が 1.89 で、プロジェクトの MSRV（1.85）を満たさないためです。
また、引用符付きの `"1"` を整数として受け付けるので、型の厳密さのためには別の対処が必要でした。

### serde_yaml

serde_norway の元になったライブラリです。
保守が終了しているので採りませんでした。

### serde_json の Value を値の木にする

値の木の型を自作せずに済みます。
しかし、`Value` から構造体を読み込むときも、列から位置で読み込む挙動が残ります。
また、YAML の `.inf` のような有限でない数値が null に変わり、整数のキーが文字列に変わります。

## 制約

- 型や構造の誤りのエラーは、宣言の中の位置をパス（`disk.d0.partitions[0].label` など）で示します。
  値の木を経由するので、YAML の行と列は示せません。
  構文の誤りと重複キーのエラーは、パーサーが示す行と列を含みます。
- serde_norway は、libyaml を Rust に機械的に変換した unsafe なコード（unsafe-libyaml-norway）に依存します。
- MSRV を 1.89 以上に上げる場合は、serde-saphyr への置き換えを検討し直します。
