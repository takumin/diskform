# 0008. ラベルの必須化と、ラベルがないことの表し方

- 状態：承認済み
- 日付：2026-10-03

## 背景

ADR 0005 では、partition、`filesystem`、`swap` の `label` を省略でき、省略した場合はラベルを書かないことにしていました。
空の文字列は、エラーにしていました。

再適用での同定方法（ADR 0011）を決めるにあたって、既存のラベルを宣言と比べる必要が生じました。
「宣言を満たしている」とは、空のディスクに `apply` したのと同じ結果になっていることなので、宣言にラベルがない場合は、既存のラベルもないことを要求します。

しかし、省略を許すと、宣言を読んだだけでは、ラベルを付けない意図と書き忘れを区別できません。
AGENTS.md 3 章は、不完全な宣言から推測しないことを求めています。

## 判断

partition、`filesystem`、`swap` の `label` を必須にします。
省略した場合は、エラーにします。

ラベルを書かないことは、空の文字列（`label: ""`）で表します。
空の文字列は、特別な意味を持たせた目印ではありません。
例で使う書き込み先（PARTLABEL、vfat、ext4、xfs、btrfs、swap）では、ラベルの欄が空であることが、そのままラベルがない状態です。
そのため、再適用の判定は、既存のラベルが宣言の文字列と等しいかという一つの比較で済みます。

空のラベルは、長さの上限と重複の検査（ADR 0007）の対象から外します。
ラベルのない要素が複数あっても、`/dev/disk/by-label/` などで衝突しないからです。

vfat では、`NO NAME`（末尾の空白を除いて比べます）をラベルとして受け付けません。
mkfs.fat はラベルを指定されないと `NO NAME` を書き込み、blkid はこれをラベルなしとして扱います。
そのため、`NO NAME` を宣言できると、空のラベルと区別できなくなります。

ADR 0005 のラベルの節のうち、`label` の省略と空の文字列の扱いは、この ADR で改めます。
ラベルの長さの上限と、重複の検査の範囲は変わりません。

## 検討した代替案

### 省略をラベルなしとする（ADR 0005 のまま）

宣言が短くなります。
しかし、書き忘れたラベルが、ラベルなしの意図として扱われます。
再適用の判定では、既存のラベルを消すべきかどうかが、書き忘れによって変わってしまいます。

### ラベルなしを `null` で表す

ADR 0006 で、`null` を拒否しています。
`null` をこの項目だけで受け付けると、規則に例外が生じます。

### ラベルなしを専用の値（`none: true` など）で表す

空の文字列とは別に、ラベルがないことを表す書き方を設ける案です。
書き込み先の側で、空のラベルとラベルなしが区別されないので、別の書き方を設けても表せる状態は増えません。

## 制約

- 既存の宣言で `label` を省略していたものは、`label: ""` を書き足す必要があります。
- vfat では、ラベルとして `NO NAME` を使えません。
