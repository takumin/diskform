# 0009. LUKS の作成パラメータ

- 状態：承認済み
- 日付：2026-10-03

## 背景

宣言の `luks` には、下位のデバイスと鍵ファイルだけを書きます（ADR 0005）。
LUKS を作るには、ほかにバージョン、暗号方式、鍵の導出関数（PBKDF）などを決める必要があります。

これらの値を cryptsetup の既定値に任せると、二つの問題が生じます。

- cryptsetup の既定値は、ビルドの設定や版によって変わります。同じ宣言から、マシンごとに異なる LUKS が作られる可能性があります。
- LUKS のデータの開始位置は、上に載る PV の大きさを決めます。開始位置が既定値に依存すると、plan が計算する VG の容量（ADR 0010）と、実際に作られる容量が食い違う可能性があります。

また、ブートローダーによっては、LUKS のパラメータが起動の可否に関わります。
メンテナーは、systemd-boot や GRUB など、複数のブートローダーで起動できる構成を求めています。

## 判断

### 固定する値

LUKS の作成パラメータは、宣言では指定させず、次の値に固定します。
cryptsetup には、既定値と同じ値であっても明示的に渡します。

| 項目 | 値 |
| --- | --- |
| バージョン | LUKS2 |
| 暗号方式 | `aes-xts-plain64` |
| 鍵長 | 512 ビット |
| PBKDF | `argon2id` |
| データの開始位置 | 16MiB |

PBKDF のメモリ量と反復回数は、cryptsetup のベンチマークに任せます。
暗号化のセクタサイズも、cryptsetup の選択に任せます。
どちらも、作られるデバイスの容量に影響しないためです。

LUKS2 を選ぶ理由は、現在の cryptsetup の既定であり、`systemd-cryptenroll` による TPM2 や FIDO2 の登録も LUKS2 を前提としているためです。

### 鍵ファイル

diskform が作る鍵スロットは、宣言の鍵ファイルによるものだけです。
パスフレーズや TPM2 などの解除手段は、利用者が後から追加します。

鍵ファイルは、内容全体を、改行の除去などをせずにそのまま鍵として使います（cryptsetup の `--key-file` の挙動です）。

鍵ファイルが存在しない場合、通常のファイルでない場合、読めない場合、空の場合は、plan と apply の両方で拒否します。
apply では、鍵ファイルを使う直前に、この確認をやり直します（AGENTS.md 3 章）。
パスフレーズの対話入力に切り替えることはしません。
`--auto-approve` を付けた非対話の実行では、入力を待ったまま止まってしまうためです。

### ブートローダーとの関係

LUKS を開くのは、ブートローダーではなく initramfs であることを前提にします。
そのため、`/boot` は暗号化の外に置く必要があります。
例では、暗号化しない ext4 のパーティションを `/boot` にマウントします。

この前提のもとでは、どのブートローダーでも、LUKS のパラメータに関係なく起動できます。

- **GRUB**：暗号化されていない `/boot` からカーネルを読みます。
- **systemd-boot**：ESP と XBOOTLDR しか読みません。Debian などでは、カーネルの導入時に kernel-install がカーネルと initramfs を ESP にコピーします。

## 検討した代替案

### cryptsetup の既定値に任せる

宣言にも diskform にも、パラメータを書かずに済みます。
しかし、背景で述べたとおり、作られる LUKS と VG の容量がビルドの設定や版に依存します。

### パラメータを宣言で指定させる

`luks` に `version` や `pbkdf` などの項目を設ける案です。
例はどの値も必要としないので、受け付ける値は一つずつになり、項目を設ける意味がありません（ADR 0007）。

### GRUB が開ける PBKDF2 にする

`/boot` を暗号化しても、GRUB で起動できます。
しかし、PBKDF2 は argon2id より、GPU などによる総当たりに弱い鍵の導出関数です。
GRUB で `/boot` まで暗号化する構成は、例が必要としていません。

### LUKS1 にする

GRUB は LUKS1 を開けます。
しかし、LUKS1 では `systemd-cryptenroll` を使えず、PBKDF2 しか選べません。

## 制約

- `/boot` を LUKS の中に置き、GRUB で起動する構成はサポートしません。
  upstream の GRUB 2.12 は、argon2id を使う LUKS2 を開けないためです。
  その構成を必要とする例が現れたら、PBKDF を宣言で指定できるようにするかを決めます。
- 作成パラメータを変えると、それ以前に作った LUKS とパラメータが異なることになります。
  再適用での判定（ADR 0011）は、暗号方式や PBKDF を比べないので、変えた後も以前の LUKS を構成済みとして扱います。
  データの開始位置を変える場合は、VG の容量が変わるので、ADR 0010 の計算とあわせて見直します。
