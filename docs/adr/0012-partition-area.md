# 0012. パーティションを置く領域

- 状態：承認済み
- 日付：2026-10-03

## 背景

ADR 0002 は、ディスクでは「パーティションテーブルが利用可能とする領域」を親の容量とし、パーティションを 1MiB の倍数に丸めることを定めています。
しかし、GPT が利用可能とする領域の先頭と末尾は、1MiB の境界に揃っていません。
512 バイトのセクタのディスクでは、先頭の 34 セクタと末尾の 33 セクタを GPT のヘッダとエントリが使います。

利用可能な領域の大きさをそのまま親の容量とすると、パーティションを 1MiB の境界から並べたときに、最後のパーティションが領域の末尾からはみ出すことがあります。

## 判断

パーティションを置く領域は、GPT の最初の利用可能な LBA から最後の利用可能な LBA までの範囲を、内側の 1MiB の境界まで縮めた範囲とします。
この範囲の大きさを、ADR 0002 の親の容量とします。

GPT のエントリの配列は、128 個のエントリを 128 バイトずつ持つ標準の大きさ（16KiB）とします。
ほとんどのディスクでは、領域の先頭は 1MiB、末尾はディスクの末尾から 1MiB 未満だけ手前の境界になります。

パーティションは、宣言の順に、領域の先頭から隙間なく並べます。

## 検討した代替案

### 利用可能な領域の大きさをそのまま親の容量にする

ADR 0002 の文言どおりですが、背景で述べたとおり、丸めの結果が領域からはみ出すことがあります。
はみ出しを防ぐには、最後のパーティションだけを別の規則で縮める必要があり、ADR 0002 の順序に依存しない計算と矛盾します。

### ディスクの容量全体を親の容量にする

GPT が使う領域を無視するので、`100%` のパーティションが作れなくなります。

## 制約

- ディスクの末尾の 1MiB 未満の端数は、どのパーティションにも使いません。
- エントリの配列が標準と異なる大きさの GPT は、作りません。
  既存の GPT のエントリの配列が標準と異なる場合の扱いは、ADR 0011 の判定を実装する時点で決めます。
  （ADR 0015 で、既存の GPT のエントリの配列の大きさは比べないことにしました。）
