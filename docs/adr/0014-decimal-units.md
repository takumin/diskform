# 0014. 十進接頭辞の単位

- 状態：承認済み
- 日付：2026-10-07

## 背景

ADR 0002 は、固定サイズの単位として二進接頭辞（`KiB`、`MiB`、`GiB`、`TiB`）だけを受け付け、十進接頭辞（`GB` など）をエラーにしていました。

しかし、ディスクの容量は十進接頭辞で表示されて販売されます。
「4TB」の HDD の容量は 4,000,787,030,016 バイトで、`4TiB`（4,398,046,511,104 バイト）より小さくなります。
例のデータディスクは `min_size: 4TiB` と宣言していたので、一般的な 4TB の HDD に一致しませんでした。
`plan` の実装中に、この不一致が見つかりました。

ディスクの照合条件（`min_size`、ADR 0003）は、製品の表示容量で書けるほうが、書き誤りを防げます。

## 判断

固定サイズの単位として、二進接頭辞に加えて、十進接頭辞の `KB`、`MB`、`GB`、`TB` も受け付けます。

| 単位 | バイト数 |
| --- | --- |
| `KB` | 10^3 |
| `MB` | 10^6 |
| `GB` | 10^9 |
| `TB` | 10^12 |

単位の綴りは、この大文字小文字の組み合わせだけを受け付けます。
SI の正式な綴りである `kB` や、`Gb` のようにビットと読める綴りは受け付けません。
二進接頭辞の綴り（`KiB`）と揃え、表記を一つに保つためです。

十進接頭辞の単位は、どの固定サイズにも使えます（partition と LV の `size`、`min_size`）。
丸めの規則（ADR 0002）は、単位によって変わりません。
たとえば、partition の `size: 1GB` は、1MiB の倍数に切り上げた 954MiB になります。

例では、ディスクの `min_size` を十進接頭辞で書きます。
partition と LV の `size` は、二進接頭辞のまま書きます。

ADR 0002 の表記のうち、十進接頭辞の単位をエラーにする規則は、この ADR で改めます。

## 検討した代替案

### 二進接頭辞だけを受け付ける（ADR 0002 のまま）

単位の意味が一つに決まります。
しかし、利用者は製品の表示容量を二進接頭辞に換算する必要があり、例でも換算を誤っていました。

### `min_size` にだけ十進接頭辞を受け付ける

ディスクの容量に関わる項目だけに限る案です。
同じ表記の意味が項目によって変わり、規則が増えます。
十進接頭辞をどこで使っても、丸めの規則によって作られる大きさは一意に決まるので、限る理由がありません。

### `GB` を二進接頭辞の意味で読む

`GB` を 2^30 バイトと読むツールもあります。
しかし、それではディスクの表示容量と一致しないという、この ADR の動機を満たせません。

## 制約

- `GB` と `GiB` は約 7% 異なるので、取り違えると、意図と異なる大きさのパーティションが作られるか、照合に失敗します。
  plan は計算後の絶対サイズを表示するので（ADR 0002）、利用者は apply の前に確認できます。
