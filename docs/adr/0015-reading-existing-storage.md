# 0015. 既存の構成の読み取り

- 状態：承認済み
- 日付：2026-10-07

## 背景

ADR 0011 は、空でない組が宣言を満たしているかを判定するために比べる項目と、状態を変えずに読めない項目が残った組を構成済みと判定しないことを定めています。
しかし、各項目をどこから読むか、どの状態のときに「状態を変えずに読めない」とするかは決めていません。
ADR 0012 も、既存の GPT のエントリの配列が標準と異なる場合の扱いを、判定を実装する時点で決めるとしていました。

読み取りを誤ると、判定を誤ります。
とくに、カーネルが認識しているデバイスとディスク上の内容がずれていると、上の層を別の領域から読んでしまうおそれがあります。

## 判断

### 各項目の読み取り

- **ディスク**：パーティションテーブルの種類と、ディスク自体の署名を、blkid の低レベルの検出（キャッシュを使わない読み取り）で読みます。
  ディスク自体にテーブル以外の署名があるか、ディスク自体の上にデバイスがある（`/sys/block/*/holders`）場合は、宣言と異なるものとします。
  空のディスクに apply しても、どちらも生じないからです。
- **パーティション**：ディスク上のテーブルを partx で読み、カーネルが認識しているパーティション（sysfs）と、番号、開始位置、大きさを突き合わせます。
  一致しない場合は、読み取りの誤りとして、組を構成済みと判定しません。
  上の層は、カーネルのパーティションのデバイスを通して読むためです。
- **署名とラベル**：パーティション、LUKS のマッピング、LV の上の署名、ラベル、UUID を、blkid の低レベルの検出で読みます。
- **LUKS の鍵**：ADR 0011 のとおり、`cryptsetup open --test-passphrase` で確かめます。
- **LUKS が開いているか**：LUKS のデバイスの holders のうち、device-mapper の UUID が `CRYPT-LUKS` で始まるものを、開いているマッピングとします。
  閉じている LUKS の上に宣言された要素がなければ、比べられない項目は残らないので、LUKS が閉じていることだけでは構成済みの判定を妨げません。
  マッピングの名前は比べません。
  ADR 0011 の比べる項目に含まれず、利用者が別の名前で開いていても、上の層の比較には影響しないからです。
- **VG、PV、LV**：pvs、vgs、lvs の JSON 形式の出力から読みます。
  活性化されていない LV の上の層は、状態を変えずに読めないものとします。
  活性化は、device-mapper のデバイスを作るからです。
- **btrfs**：マウントされている btrfs に限り、デバイスの集合とプロファイルを sysfs（`/sys/fs/btrfs/<UUID>`）から、subvolume を `btrfs subvolume list` で読みます。
  マウントされていない btrfs は、状態を変えずに読めないものとします。

### 比べ方

- パーティションの開始位置と大きさ、LV の大きさは、計算結果との差がアラインメントの単位（パーティションは 1MiB、LV は PE のサイズ）以下であれば一致とします（ADR 0002）。
- GPT の種類は、`type` を省略したパーティションを Linux のファイルシステムの種類（`0FC63DAF-8483-4772-8E79-3D69D8477DE4`）として比べます。
- GPT のエントリの配列の大きさは比べません。
  パーティションの位置を比べるので、配列の大きさが異なっても、パーティションの位置が一致していれば、空のディスクに apply した結果と同じ領域を使っています。
- btrfs のプロファイルは、宣言に `btrfs` の指定がある場合に限り比べます。
  データとメタデータのそれぞれで、存在するプロファイルが宣言のものだけであることを求めます。
  変換の途中で複数のプロファイルが混在している場合は、異なるものとします。
  `btrfs` の指定がない場合、apply が作るプロファイルは宣言で定まっていないため、比べません。

## 検討した代替案

### マウントせずに btrfs を読む

`btrfs inspect-internal dump-tree` は、マウントせずにチャンクの種類や subvolume を読めます。
しかし、その出力は人が読むためのもので、形式が安定していません。
解析の誤りは判定の誤りに直結するので、採りません。

### カーネルのパーティションだけを読む

blkid でパーティションのデバイスを調べれば、パーティションのエントリも読めます。
しかし、ディスク上のテーブルにあってカーネルが認識していないエントリを見落とします。
宣言より多いエントリを見落とすと、異なる構成を構成済みと判定します。

## 制約

- 再適用で構成済みと判定させるには、LUKS を開き、LV を活性化し、btrfs をマウントしておく必要があります。
- btrfs のマウントを探すのは、diskform を実行したマウント名前空間の中だけです。
- 読み取りの多くは特権を必要とするので、plan は実質的に root で実行することになります。
