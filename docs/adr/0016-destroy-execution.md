# 0016. destroy の読み取りと消去の手段

- 状態：承認済み
- 日付：2026-10-07

## 背景

ADR 0004 は、`destroy` の対象の指定、複数のディスクにまたがる構成の検査、使用中のデバイスの扱い、消去の範囲、確認の方法を定めています。
しかし、対象ディスクの上にある構成をどこから読むか、署名をどの手段で消すか、確認の後に状態が変わっていた場合と、途中で失敗した場合にどうするかは決めていません。

`destroy` は、データを消す唯一のサブコマンドです。
読み取りを誤ると、消去してはいけないデバイスを消去するか、消去したつもりの署名を残します。

## 判断

### 対象ディスクの上にある構成の読み取り

対象ディスクのパーティションは、ADR 0015 と同じく、ディスク上のテーブルを partx で読み、カーネルが認識しているパーティションと突き合わせます。
一致しない場合は拒否します。
カーネルが認識していないエントリの中の署名は、パーティションのデバイスを通して消せないからです。

ディスクとパーティションの上に作られたデバイスは、`/sys/class/block/*/holders` を上にたどって集めます。
device-mapper のデバイスの種類は、その UUID で判別します。

- `CRYPT-LUKS` で始まるものは、開いている LUKS のマッピングです。
- `LVM-` で始まるものは、活性化された LV です。
- それ以外は、種類を判別できないものとして拒否します。

上にたどって集めたデバイス、パーティション、ディスクのどれかが使用中であれば、拒否します。
使用中の判定には、次を使います。

- `/proc/self/mountinfo` のマウント元のデバイス（デバイス番号とパス）
- `/proc/swaps` の有効な swap
- `/sys/fs/btrfs/<UUID>/devices` に現れる、マウントされた btrfs のデバイス

btrfs を別に調べるのは、複数のデバイスから成る btrfs では、マウントの情報にデバイスが一つしか現れないためです。

### 複数のディスクにまたがる構成のメンバー

ADR 0004 の二つの検査（宣言の完全さと対象の過不足）のために、対象ディスクの上で見つけた構成のメンバーを、次のように集めます。

- **VG**：PV の署名があるデバイスと、活性化された LV について、pvs の出力から VG と、その VG の PV を読みます。
  pvs が見つけられない PV は、欠けているメンバーとして示します。
- **btrfs**：このマシンのすべてのブロックデバイスを blkid の低レベルの検出で読み、同じ UUID の btrfs を集めます。
  `btrfs inspect-internal dump-super` の `num_devices` より少なければ、欠けているメンバーがあると示します。

各メンバーがどのディスクの上にあるかは、パーティションからはそのディスクへ、device-mapper のデバイスからは `slaves` へ、下にたどって決めます。

メンバーのあるディスクが宣言のどのディスクかを示すために、対象にしないディスクも含めて、宣言のすべてのディスクを ADR 0003 で照合します。
照合できないディスクがあれば、拒否します。

md のアレイ（md のデバイスと、md のメンバーの署名）は、拒否します。
ADR 0004 は稼働中の md のアレイを解除して消去するとしていますが、md を使う例がまだないため、解除と検査を実装していません。
md を使う例が現れたときに、実装して検証します。

### 解除と消去の手段

解除と消去は、次の順で行います。

1. 活性化された LV があれば、その VG を `vgchange --activate n` で非活性化します。
2. 開いている LUKS のマッピングを `cryptsetup close` で閉じます。
3. 署名のある各パーティションを、`wipefs --all` で消去します。
4. ディスクを `wipefs --all` で消去します。
   カーネルにパーティションが残っていれば、`partx --delete` で取り除きます。

解除は、上に作られたデバイスがすべて解除されたものから順に行います。
消去の後に、各ディスクが空（ADR 0011 の空の判定）であることを確かめます。

消去に `wipefs` を使うのは、blkid が検出するすべての署名を、副本も含めて消すからです。
実際に、LUKS2 の二つのヘッダと、GPT の先頭と末尾のテーブルと保護 MBR を消すことを確かめました。
`--force` は付けません。
`wipefs` は消去するデバイスを排他的に開くので、使用中の判定で見落としたデバイスも、カーネルが拒否します。

### 確認の後の再検証

確認を得た後、読み取りと計画をやり直し、表示した操作と一致することを確かめてから実行します。
一致しなければ、何も変更せずに止めます。
確認を待つ間に、デバイスの状態が変わりうるからです。

### 途中で失敗した場合

最初に失敗した操作で止め、完了した操作、失敗した操作、その時点の各ディスクの状態を示します。
自動で再試行も復旧もしません。
`destroy` をもう一度実行すると、その時点の状態から計画を作り直します。

## 検討した代替案

### パーティションテーブルの編集ツールで消去する

`sgdisk --zap-all` は、GPT と MBR のテーブルを消します。
しかし、パーティションの中の署名やディスク全体に直接書かれた署名は消しません。
ADR 0004 が求める範囲を一つの手段で消せる `wipefs` を選びました。

### 先頭の領域をゼロで上書きする

各デバイスの先頭の数 MiB をゼロで上書きする案です。
GPT の末尾のテーブルや、LUKS2 の二つ目のヘッダのように、先頭以外にある署名を残します。
署名の位置は形式ごとに異なるので、それを知っている blkid に任せます。

### btrfs のメンバーを `btrfs filesystem show` で読む

マウントしていない btrfs のデバイスの一覧と、欠けているデバイスを表示します。
しかし、出力は人が読むための形式です。
ADR 0015 と同じ理由で、メンバーは blkid で集め、欠けている数だけを `dump-super` の値で比べます。

## 制約

- 閉じている LUKS の中にあるメンバー（他のディスクの、閉じた LUKS の中にある PV など）は見つけられません。
  そのメンバーは、検査の対象になりません。
- 対象ディスクの上に btrfs がある場合、このマシンのいずれかのブロックデバイスを blkid で読めない（複数の署名が衝突しているなど）と、メンバーを集められないので拒否します。
- md のアレイを含むディスクは、`destroy` できません。
- `destroy` は実質的に root で実行することになります。
