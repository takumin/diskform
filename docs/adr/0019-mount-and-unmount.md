# 0019. mount と unmount の実行

- 状態：承認済み
- 日付：2026-10-13

## 背景

ADR 0004 は、`mount` が LUKS を開き、VG を活性化し、ファイルシステムを `--root` の下にマウントすること、`unmount` がその逆を宣言の構成だけに対して行うことを定めています。
swap は有効にせず、fstab や crypttab は生成しません。

しかし、マウントする前に何を確かめるか、どの順で開くか、マウント先がすでに使われている場合や、解除するデバイスがほかで使われている場合にどうするかは決めていません。

`mount` は、宣言と異なる構成を開いてマウントするおそれがあります。
照合したディスク（ADR 0003）が意図したものでなければ、利用者は別のマシンのデータを書き換えることになります。
一方、ADR 0011 の判定は、閉じている LUKS の上の層を状態を変えずに読めないので、開く前に構成全体を宣言と比べることはできません（ADR 0015）。

## 判断

### mount の確認と順序

`mount` は、すべての組を plan と同じく ADR 0011 で判定します。
宣言と異なる点が一つでもあれば、何も開かずに拒否します。
組のディスクがすべて空であれば、マウントするものがないので拒否し、先に apply を実行するよう示します。

判定が状態を変えずに読めなかった層は、一段ずつ開いては判定し直します。

1. 閉じている LUKS を、宣言の名前と鍵ファイルで開きます。鍵ファイルは、使う直前に確かめ直します（ADR 0009）。
2. 判定し直し、活性化されていない LV があれば、その VG を活性化します。
3. 判定し直し、違いがなく、マウントされていない btrfs のほかに読めない項目がなくなるまで繰り返します。

このため、ある層を開くのは、その下の層がすべて宣言どおりだと確かめた後に限られます。
たとえば、LUKS のヘッダや鍵が宣言と合わなければ、VG は活性化されません。

btrfs は、マウントしないとデバイスの集合、プロファイル、subvolume を比べられません（ADR 0015）。
そこで、btrfs をマウントする前に、このマシンにある同じ UUID のデバイスが宣言のデバイスとちょうど一致し、その数がファイルシステムのデバイス数と等しいことを確かめます（ADR 0016 と同じ読み取り）。
すべてをマウントした後に、もう一度判定し、違いがあれば失敗とします。
マウント先を持たない btrfs はマウントしないので、その btrfs が読めないことは失敗にしません。

### マウントの方法

マウントするのは、`mount` を持つファイルシステムと、`mount` を持つ subvolume です。
マウント先のパスの順に、上にあるものから先にマウントします。
`--root` の下のパスは、宣言のマウント先から先頭の `/` を除いたものです。

- マウントのオプションには、宣言の `mount_options` を渡します。
- subvolume は、ファイルシステムの `mount_options` に `subvol=<path>` を加えてマウントします。
- 複数のデバイスから成る btrfs には、すべてのデバイスを `device=` で指定します（ADR 0018 と同じ理由です）。

マウント先のディレクトリがなければ作ります。
上にマウントしたファイルシステムの中に、下のマウント先のディレクトリがまだないことがあるためです（apply が作ったばかりのルートファイルシステムなど）。
diskform がファイルシステムの中に書き込むのは、この操作だけです。

マウント先に、同じデバイス（subvolume では同じ subvolume）がすでにマウントされていれば、何もしません。
別のものがマウントされていれば、拒否します。
これにより、`mount` を繰り返し実行しても、同じ状態になります。

### unmount の確認と順序

`unmount` は、何かを変更する前に、次の三つを確かめます。

- `--root` の下にあるマウントは、すべて宣言のマウント先で、宣言のディスクの上のデバイスからマウントされていること。
  宣言にないマウントがあると、ルートのアンマウントが途中で失敗するためです。
- 非活性化する VG の PV が、すべて宣言のディスクの上にあること。
- 閉じる LUKS のマッピングと非活性化する LV が、`--root` の下の宣言のマウント先のほかで使われていないこと。
  ルートの外のマウント、有効な swap、宣言にない holders があれば、拒否します。

`unmount` は swap を無効にしません。
`mount` が有効にしないので、有効な swap は利用者が有効にしたものです。

確認の後、マウントを後に作られたものから順にアンマウントし、宣言の VG を非活性化し、宣言の LUKS のマッピングを閉じます。
各操作の後に、その結果を読み直して確かめます。
解除するものがなければ、何もせずに成功します。

`mount` と `unmount` は、確認を求めません。
どちらもデータを消さず、もう一方で元に戻せるからです。

### 途中で失敗した場合

どちらも、最初に失敗した操作で止め、完了した操作を示します。
自動で元に戻すことはしません。
`mount` の途中で止まった場合は、`unmount` で解除できます。

## 検討した代替案

### 開く前に判定しない

`mount` が宣言の順に開いてマウントするだけにする案です。
しかし、照合したディスクが意図したものでない場合に、別の構成を開いてマウントします。
ファイルシステムは、読み書き可能でマウントするだけでジャーナルの再生などで変更されることがあります。

### すべてを開いてから一度だけ判定する

LUKS と VG をすべて開いてから判定する案です。
判定の回数は減ります。
しかし、LUKS のヘッダが宣言と違っても VG を活性化してしまいます。
一段ずつ開けば、開く層の下は常に確かめられています。

### btrfs を読み取り専用で一時的にマウントして判定する

宣言の場所にマウントする前に、プロファイルと subvolume を比べられます。
しかし、btrfs は読み取り専用でもログを再生することがあり、ディスクを変更しないことは保証されません。
デバイスの集合をマウントの前に確かめれば、別の btrfs をマウントするおそれは小さくなります。

### unmount が swap も無効にする

`destroy` の前の準備が一度で済みます。
しかし、`mount` は swap を有効にしないので、有効な swap は利用者が使っているものです（ADR 0004 の `destroy` と同じ理由です）。

### unmount で、ルートの下のマウントを再帰的にアンマウントする

`umount --recursive` は、宣言にないマウント（インストーラが作った `/proc` など）もアンマウントします。
対象を宣言の構成に限る ADR 0004 と合いません。

## 制約

- `mount` は、判定（ADR 0011）を最大で層の数だけ繰り返します。判定のたびに鍵ファイルで LUKS の鍵スロットを試すので（`--test-passphrase`）、PBKDF の計算の時間がかかります。
- `mount` はマウント先のディレクトリを作ります。宣言のファイルシステムの中に、空のディレクトリが残ることがあります。
- マウントを調べるのは、diskform を実行したマウント名前空間の中だけです（ADR 0015 と同じです）。
- `unmount` は、宣言の構成を使っているプロセスを止めません。アンマウントや非活性化が使用中で失敗した場合は、その時点で止まります。
